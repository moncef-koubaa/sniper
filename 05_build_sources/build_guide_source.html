1. What this system is, in one page

An internship search for one final-year engineering student, run by Claude Code on the PC. Each command is started by hand and, once started, Claude:

  • finds internship opportunities in one country at a time (companies and startups first, then labs, universities and job boards),
  • checks each one: is it still open, who is the right contact, will they take a non-EU student and sign {{SCHOOL}}'s internship agreement,
  • applies: writes a tailored CV and cover letter for each one, submits company portal forms, and sends application emails,
  • and reads the mailbox: files every reply, updates each application's status, answers the simple emails, sends due follow-ups, and prepares options for the important ones.

The student only does what a machine should not: answers interview invitations and offers, clicks LinkedIn "Easy Apply", logs in where a password is needed, and answers the rare form question the system cannot answer truthfully.

What runs itClaude Code (the command-line Claude) on the Windows PC. You type a command; nothing runs on a schedule.
What it remembers withOne spreadsheet file, tracker.csv. Every opportunity is one row. No chat history is needed.
What it works throughYour Chrome (already logged in to your sites), your Gmail, Google Drive and Calendar, the web, and Python scripts.
What keeps it safeHard rules in CLAUDE.md, a 50-email daily cap, a "holds" list, a saved answers file for forms, and checks before every email.

2. How it works: the five ideas that explain everything

Idea 1. The memory is a file, not a conversation

Every run is a fresh Claude session that knows nothing. It reads 02_tracker\tracker.csv, works on some rows, writes the results back, writes a report, and ends. Closing a session loses nothing. Every command writes the tracker right after each row it works on, so a run cut short loses nothing.

Each opportunity row moves through a fixed set of statuses:

discoveredfound by Hunter
→
enrichedchecked + scored by Checker
→
queueddocuments + draft ready
→
appliedsent or submitted
→
repliesacknowledged · interview · offer · rejected · no_response

Side exits: screened_out / expired (dead: moved to seen.csv so it is never found again) and blocked (needs a human: moved to blocked.csv, your manual queue).

Idea 2. One job per run

Each kind of work is a separate "run" with its own instructions, a slash command. A Hunter never applies, an Applier never hunts. This keeps every run small and predictable.

Idea 3. You start each run; no run has a limit

Nothing is scheduled. You open Claude Code in the folder and type the command you want. gate.py can tell you which commands have work. No run has a row, search, helper or spending cap; only email is capped.

The tracker is updated after every row. Every command writes each row (and each action on it: status, enrichment, documents, submission, send, reply, block) through tracker_tools the moment it is done, never at the end. Big runs can reach your Claude plan's 5-hour usage limit or fill the session: the run then stops, everything done so far is saved, and running the same command again continues (the Applier from its PROGRESS file). Every report says how many rows were covered and how many remain.

How the Hunter chooses countries

You never choose. 01_sources\country_priority.csv ranks the countries you gave the setup (at least 10) by fit with your profile (language, visa for a {{NATIONALITY}} student, match with your tracks, realistic chance). The Hunter stays on one country, run after run, going through all its offers and organisations, every source and every track (track ALL), with no row or search limit, until the country is exhausted (every source and track done and its last 20 searches found no new row). Then it marks it exhausted and moves to the next. After the last one, it researches the next 15 most compatible countries itself, adds them to the file, and carries on. Each row of the file shows the status (pending, active, exhausted), runs, rows added and last run.

Idea 4. Instructions live in text files

  • CLAUDE.md holds the rules that apply to every run: who the student is, what the internship must be, what may never be invented, how to write, how to use the browser. Claude Code loads it automatically in this folder.
  • .claude\commands\pfe-*.md hold each run's job: one Claude Code prompt per command (version 3 merged the original Cowork prompts and their Claude Code adaptations into one text). $ARGUMENTS is whatever you type after the command.
  • 00_profile\ holds the facts: verified profile, defensible claims, tracks, keywords, and the saved form answers.

Idea 5. Machines do volume, people do decisions

Portals and emails go out automatically, but only after checks (section 8). Anything with consequences, such as an interview, an offer, salary, a visa question or a password, stops and waits for you, either in /pfe-send or in blocked.csv.

8. The safety rules: sending, forms, holds

When an email goes out by itself

Applications, follow-ups and simple inbox replies are sent with send_message on a finished Gmail draft (never by clicking Send in Chrome), and only if all five checks pass. Otherwise the draft waits and the report lists it. With the word draft (/pfe-applier 20 email draft) the Applier only makes the drafts and sends nothing: /pfe-send sends the ones you name, after the same checks.

1 Qualityswap test, no banned words, no em dash
→
2 New addressverified, never emailed before
→
3 Not heldholds.csv, interviews, decisions waiting
→
4 AttachedCV + letter PDFs on the draft, read on the Gmail Drafts list
→
5 Under cap< 50 cold emails today
Never automaticReplies about interviews, offers, salary, contracts, visa or legal questions are always A/B/C drafts for /pfe-send. And remember: an email that went out cannot be unsent.
Unpaid or low-paid offers (10 Oct 2026)You have no personal or {{SCHOOL}} funds. A host that would take you unpaid, or for a very low allowance, is negotiated, never declined, and no draft says you fund yourself. The drafts first look up what that position pays in that country (or Europe) and the anchors: the visa proof of means (Spain about 600 EUR a month), the legal intern minimum (France about 630 EUR a month in 2026), grants such as Erasmus+ KA171. Then they ask for one concrete monthly figure, up to the average plus 200 to 300 EUR when the host has the means, tied to an outside requirement ("The Spanish consulate asks for proof of about 600 euros per month..."), with alternatives: partial allowance, housing, a grant, a project contract. The report lists the figures and their sources.

Portal forms

Filled from 00_profile\FORM_ANSWERS.md and submitted without asking. Saved choices (the setup asks them once): email always {{GMAIL_ACCOUNT}}; grades only as {{GRADES_EN}}; gender, date of birth, postal address, salary wording and diversity default as you answered (or NEEDS_ANSWER); {{NATIONALITY}}, needs a visa, handles it with the host's letter; {{SCHOOL}} signs the internship agreement; available {{PFE_WINDOW}}, 26 weeks.

The form asks forWhat happens
Anything answerable truthfully from FORM_ANSWERS.mdFilled and submitted.
Passport/ID number or upload, GPA, a numeric salary, postal code, a legal visa declaration, or anything else not in the fileNot submitted. Row goes to blocked.csv as NEEDS_ANSWER with the exact question.
CAPTCHA, account creation, a login you are not signed in to, LinkedIn Easy Apply, Indeed ApplyNever attempted. Row goes to blocked.csv as BLOCKED.

Holds: stopping one company

02_tracker\holds.csv lists rows nothing automatic may send to or submit. Only you remove lines. Two holds are automatic and need no line: every other row of a company where you have an interview or offer, and any address already emailed once. Never apply to {{EXCLUDED_ORGS}}.

Rules that never change

  • Never invent a contact, address, deadline or result; never build an email address from a pattern.
  • Your own work stays separate from team work in every document.
  • Grades only as {{GRADES_EN}}, nothing else: no other mark, average or exact rank.
  • Maximum 50 cold emails a day; portals carry the volume.
